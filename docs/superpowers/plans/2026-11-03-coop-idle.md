# Co-op idle ownership implementation plan

> Execute inline with systematic debugging, TDD and one final code review.

**Goal:** retain native idle-camera/HUD transitions while preventing two actors
from overwriting one global idle tracker; activity on either co-op port keeps
the shared HUD awake.

**Architecture:** opt-in `sr_coop_idle` depends on co-op input and the owned P2
camera. Validate the current input slots, target and camera binding. Only P1
updates the native global tracker. During that exact update's input-idle query,
use the minimum valid idle duration from ports 0 and 1. No actor/camera/HUD
globals are rebound. Absent/invalid bindings preserve original behavior.

**Scope:** existing experimental probe, C++ hooks plus portable policy tests.
Flash per-player bars/layout and arbitrary cutscene ownership remain pending.
The previous HUD-after-leave observation is reclassified only with runtime
evidence of native idle entry and input-triggered recovery.

Ruling: normalize native secondary input-time residues in [-0.001,0] to zero.
The first P2-only input run returned approximately -7 microseconds from float
timestamp rounding; treating this as invalid could trigger idle during activity.
A regression test was observed failing two checks before the change. Larger
negative/non-finite secondary values still preserve the native primary result.
