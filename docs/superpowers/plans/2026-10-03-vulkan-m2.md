# Vulkan M2 — Frontend compartilhado e shaders do jogo

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer o renderer D3D12 consumir interpretação guest compartilhada e produzir shaders SPIR-V do jogo com ABI, requisitos e cache verificáveis para a integração Vulkan posterior.

**Architecture:** Extrair decisões puras do renderer existente, preservando hooks, PM4 e sincronização guest. Acrescentar uma variante de emissão Vulkan com constantes em buffers e descritores de tamanho fixo, sem endereços de GPU no shader. DXIL continua usando o caminho atual; SPIR-V tem ABI e cache próprios. Validar os contratos com fixtures sintéticos e dados locais reais, sem habilitar Vulkan no jogo neste marco.

**Tech Stack:** C++20/23, harness `tests/native`, Python unittest, DXC 1.9.0.5402 existente, XenosRecomp pin `339af41df2c23dbe3256c1c377716b81a0e0fe6b` com patches do projeto, Vulkan 1.1/SPIR-V 1.3.

**Spec:** `docs/superpowers/specs/2026-10-03-vulkan-backend-design.md`, arquitetura aprovada, seção M2. Baseline M1: `1710798`; branch `codex/vulkan-backend`.

## Global Constraints

- Reaproveitar a interpretação guest; não criar um segundo parser PM4 para Vulkan.
- Núcleo compartilhado sem HWND, COM, handles Vulkan ou Direct3D.
- Preservar o renderer D3D12 como referência e padrão; launcher não oferece Vulkan ainda.
- Preservar correções de vídeos, USHORT2 do HUD e separadores de War World.
- Guest fences/interrupções continuam no sistema atual; nenhum novo protocolo de sincronização guest.
- Shaders derivados do jogo, capturas e caches ficam ignorados/localmente; commits e distribuição contêm somente fontes, patches e fixtures próprios.
- Não implementar texturas/untile, render targets, apresentação do jogo, APK ou runtime ARM64 neste marco.
- Preservar alterações locais do launcher e native_graphics_system.cpp, com stage seletivo.
- Não habilitar BDA, shaderInt64, descriptor indexing, arrays runtime ou extensões desktop por consequência do caminho SPIR-V legado.
- Capacidades efetivamente usadas devem ser reportadas; Vulkan 1.1 não significa que toda GPU oferece os limites/features necessários.

## Review Focus

1. Dados capturados não podem consultar memória guest já alterada: snapshot com ownership e limites testados — Task 1.
2. Restart/endian/USHORT2 não podem regredir ao extrair helpers — Task 1.
3. DXIL antigo não pode ser interpretado como SPIR-V nem cache antigo reutilizado após mudança de bindings/emissor — Task 3.
4. Shader compilar não prova layout, capacidades ou matching VS/PS: reflexão e teste de execução são necessários — Tasks 2/4/5.
5. Timeout, shader inválido ou capability não suportada devem falhar claramente, sem substituir por D3D12 ou marcar shader pronto — Tasks 3/4.

## Levantamento confirmado

`Renderer::WorkCmd`, `BufferPlan` e `StreamPlan` já representam trabalho capturado, mas são privados em `native_renderer.h`. `index_endian.h`, `Pm4Mirror` e `texture_binding.h` já têm decisões sem D3D12. `BindConstants` sanitiza NaN e produz 4096 bytes de constantes por estágio. A metadata de vertex fetch tem 224 entradas de 16 bytes.

O corpus local informa 241 shaders únicos, 240 DXIL compilados e um shader com erro conhecido de parâmetro duplicado. Seu campo `spirv_ok=0` não prova que todos falharam: registrar se houve tentativa e os diagnósticos antes de comparar. O helper SPIR-V atual usa `uint64_t`, `vk::RawBufferLoad`, push constants com endereços e descriptor heaps sem tamanho; não serve como ABI portátil do M2.

## Task 2: ABI Vulkan explícita no emissor HLSL

**Files:** criar `tools/shaders/xenosrecomp/patches/0011-vulkan-buffer-bindings.patch`, `port/src/graphics/shaders/binding_contract.h`, `tools/shaders/vulkan_contract.py`, `tests/shaders/test_vulkan_contract.py`; modificar `tools/shaders/fetch_xenosrecomp.py` apenas para detectar alteração de conteúdo dos patches na stamp.

**Interfaces:** `BindingContractVersion = 1`; ABI `sr-vulkan-buffers-v1`.
- set 0: bindings 0/1 = constantes VS/PS (4096 bytes cada), binding 2 = shared buffer de bytes com offsets atuais; usar ByteAddressBuffer/StorageBuffer para layout exato, inclusive booleans, loops e vertex-fetch.
- set 1: bindings 0/1/2 = arrays de Texture2D/3D/Cube com 32 elementos; set 2 binding 0 = 32 samplers; set 3 binding 0 = 32 buffers de vertex fetch. Remapear índices de heaps D3D12 para índices locais por draw no consumidor Vulkan futuro; nenhum índice DXGI/SRV global atravessa esse contrato.
- Shared metadata mantém 224 entradas por semantic; `VertexFetchMeta.buffer` representa uma das 32 posições locais, não semantic nem endereço host. Relatório explicita limites de descritores; não declarar compatibilidade mobile universal.
- No emissor/helper upstream, adicionar variante explícita `SR_VULKAN_BUFFERS` para trocar todos os RawBufferLoad de constantes por `.Load/.Load4` com `asfloat`, preservando offsets. Usar `g_SpecConstantsRuntime` como no DXIL. Macro desligado deixa saída DXIL existente equivalente.
- `compile_arguments(stage: str) -> list[str]`: `-spirv -fspv-target-env=vulkan1.1 -D SR_VULKAN_BUFFERS=1 -HV 2021 -all-resources-bound -T vs_6_0|ps_6_0`; layout via byte buffers, sem depender de scalarBlockLayout. Inverter Y somente no VS por `-fvk-invert-y`; não duplicar inversão no viewport. Preservar clipping Z 0..1.
- `build_contract() -> dict` gera descrição para testes/metadata. Locations VS devem cobrir todos os semantics usados no corpus; matching VS-output/PS-input por semantic e índice, incluindo atributos inteiros e builtins. Fixar e testar a tabela do emissor em vez de interpretar locations implícitos como ordem DXIL.
